# 宿主成长系统

**在线试玩(静态版,存档在浏览器本地):** https://wumengwufeng.github.io/growth_system/
> 静态版说明:任务发布引擎、存档、全部数值逻辑均在浏览器本地运行,可直接玩;仅「AI 动态生成任务 / 复盘对话」需要本地 Magpie 网关,静态 demo 中此入口不可用。

系统流小说风格的个人成长系统：系统每天在「活跃窗口」内**随机时刻**发布任务，任务由本地 Magpie 网关的 AI 按你的目标动态生成，完成得 EXP / 金币 / 四维属性，金币可在商城兑换自设的现实奖励。

> UI 与结构对齐 `D:\project\ai_project\xuexun`（学循）的设计体系：侧边栏导航 + 卡片布局 + 浅绿纸感主题（晨白），另保留深空暗色主题可切换。核心逻辑（发布引擎 / AI 生成 / 奖励结算）与 UI 分离，改动 UI 不影响逻辑。

## 启动

**桌面版（推荐）**：双击 `宿主成长系统.pyw` —— 原生独立窗口（WebView2，无地址栏标签页），无控制台黑窗。存档持久化在 `%LOCALAPPDATA%\growth_system_webview`。

- **关窗不退到后台进程，而是收进托盘**：点窗口 × 只隐藏窗口，程序与提醒继续运行，到点照样弹 toast。托盘图标**单击/双击唤回面板**，右键「打开面板 / 开机自启 / 退出」，**「退出」才真正结束进程**。
- **托盘图标是程序的一部分**（品牌绿六边形，`assets/icon.ico`，窗口标题栏/任务栏同图）。图标由**独立线程里的 tkinter 窗口**托管，不挂在面板窗口上——面板窗口跑的是 .NET 消息循环，`Shell_NotifyIcon` 挂上去能看见图标但点击/右键收不到消息（真机上实测过）。tkinter 宿主是 `提醒服务.pyw` 一直在用的做法。
- **托盘排障看 `data/tray.log`**：pythonw 没有控制台，加图标成功与否、点击/右键（鼠标划过不记，避免刷屏）、图标迁移与重挂、右键菜单选择、拦到的关窗都会记在这里。点击没反应时先看它：没有「收到托盘消息」＝消息没进来；有但无反应＝处理分支的问题。
- 单实例：占 `127.0.0.1:8768` 做锁。已经收在托盘里时再双击桌面版，不会起第二个窗口，而是把原来那个唤回来。
- **右键菜单必须用 `TPM_RETURNCMD` 直接取选中项**，不靠 `WM_COMMAND`：窗口过程被子类化后那条消息会漏掉，而 `TrackPopupMenu` 不带 `TPM_RETURNCMD` 时只返回布尔 `1`，拿不到菜单 ID——症状就是「右键菜单点『退出』毫无反应」。`data/tray.log` 里出现 `cmd=1` 或 `未知菜单项` 即说明这个坑复发。
- **托盘图标必须挂在顶层窗口上**：`winfo_id()` 给的是 Tk 的子窗口（class `TkChild`），而广播消息（`TaskbarCreated`、探活）**只送给顶层窗口**。挂在子窗口上时资源管理器一重启就收不到 `TaskbarCreated`，图标再也挂不回来——症状是「收进托盘一段时间后自己掉了，程序看不到」。现在用 `GetAncestor(GA_ROOT)` 找顶层外壳，外壳建得晚就由 `_ensure_owner()` 每轮把图标迁过去。
- **托盘自检**（每 ~15s 一次）：shell 窗口句柄变了（资源管理器重启）、或图标状态被标成没挂上，就自己重挂，不用等人去点。
- **托盘宿主探活走锁端口的 socket**（发 `ping`，回 `pong`）：早先靠广播 `WM_PROBE`/`WM_PONG`，托盘窗口是子窗口收不到、探活方又不抽消息，于是日志里永远「应答 0 次」，等于没有探活。现在若锁被占却 ping 不通，才判定为残留进程并尝试唤回。
- **托盘轮询整轮回调包了 try/finally**：以前 `_drain` 抛一次异常，`after` 链就断在半路——图标还在、却再也不理点击，也不报错也不退出（最难查的那种）。现在异常记 `Tk 回调异常` / `托盘轮询异常` 并照常续命。
- **pythonw 没有 stderr**：`data/stderr.log` 接住了原本会被丢掉的 traceback（`redirect_stderr()`）。
- **「退出」走 `os._exit`**：`window.destroy()` 只关窗口，pywebview 的 .NET 消息循环可能继续空转，留下看不见也关不掉的进程；watchdog 兜底（托盘心跳停了**且**面板不可见才自己退出——注意 `Window.hidden` 从不更新，可见性要问 `IsWindowVisible`）。
- **GUI 循环结束时不能一声不响地退出**：睡眠唤醒后（真机 18:38 从 S3 恢复）出现过 `webview.start()` 直接返回，`main()` 走到底 `return 0`——进程消失，日志没有、崩溃记录也没有，用户只看到「托盘又不见了」。现在这条路会记 `webview.start() 已返回` 并**自动拉起新进程**（`restart_self`），10 分钟内最多 3 次，超了只记日志，避免崩溃循环弹窗。
- **每 10 分钟一条心跳**（`心跳：面板可见=… 托盘=…`）：进程被硬杀（蓝屏、任务管理器、驱动重置）时，日志里至少能看到最后活着的时间，否则只剩一片空白。
- 为什么这么做：与系统流小说里「系统随时在线」的设定对齐——以前关窗即退出、提醒也跟着停，等于系统只在你看的时候存在。
- 托盘拿不到的环境（`Shell_NotifyIcon` 被拒）会退回普通窗口行为：关窗即退出，绝不留看不见的进程。

浏览器模式（备用）：双击 `启动系统.bat`，在浏览器打开本系统的地址。注意两种模式的 localStorage 相互独立。

**端口**：默认 `8765`，可用环境变量 `GROWTH_PORT` 覆盖。若该端口已被**其他程序**占用，系统会自动改用下一个空闲端口——绝不会把别人的页面当成本系统打开（靠 `/api/ping` 身份探测区分「自己」和「别人」）。`启动系统.bat` 会从 `data/port.txt` 读取实际端口。

**常驻提醒服务（可选，与桌面版互补）**：双击 `启动提醒服务.bat`，独立托盘进程，不开面板窗口，到发布时刻弹 Windows toast。

- 桌面版关窗后已在托盘里常驻并自带提醒，这时候本服务会**自动让路**（启动即退出、轮询时也不弹窗），避免两个托盘图标和同一槽位弹两遍；桌面版真退出后它自动接回。
- 开机自启：双击 `设置开机自启.bat`（或任一托盘右键勾选），会在启动文件夹建立快捷方式，**无需管理员权限**。自启项指向**桌面版**（一个进程搞定提醒 + 唤面板）。再执行一次即关闭。
- 单实例：用 `127.0.0.1:8769` 占位做锁，重复启动会静默退出，不会出现多个托盘图标或重复提醒。
- `启动提醒服务.bat` 先探桌面版的 8768：桌面版在跑就不启动本服务（否则托盘上两个图标，分不清哪个是哪个）。要单独跑，先从托盘退出桌面版。
- 托盘点击靠 `NIF_MESSAGE` + 子类化窗口过程接收真实 `WM_TRAYICON` 消息（**不是**轮询全局鼠标按键——那样不知道光标在哪，双击也永远收不到）。**窗口过程里绝不能碰 Tk / pywebview 的 API**：托盘服务的窗口过程在 Tk 处理消息时被回调，重入 Tcl 会硬崩（`PyEval_RestoreThread` 致命错误）；桌面版的窗口过程在 .NET UI 线程上，重入 pywebview 会自锁。两边都只把事件入队，交给独立线程去调 API。资源管理器重启后会广播 `TaskbarCreated`，收到时先删图标再加回。
- 已通知状态落盘在 `data/notified.json`：只放内存的话，托盘每次重启都会把同一条提醒再弹一遍。
- 不连弹：一轮轮询里多个槽位同时到点（电脑睡醒/关机一天后回来）会合并成一条 toast，不会一次糊满屏幕；面板打开后错过的任务按「看到的那一刻」重新计时（见下方「错过提醒的补救」）。
- 存档只读：提醒服务**不写** `data/growth.json`，仅读取并计算发布时刻（与 `js/core.js` 的确定性算法一致，由 `tests/plan_parity.py` 对拍保证）。

## 要点

- **任务发布**：以日期为随机种子决定每天 2~3 个发布时刻，打开面板时补结算你不在时发布的任务；突发限时任务奖励 ×2，2 小时不响应即收回。
- **AI 生成**：默认走本机 Magpie（`/api/v1` 同源代理 → `127.0.0.1:3425`，模型 `auto/deepseek-v4.1-flash`）。网关离线时自动降级为内置任务池，不会中断。
- **奖励数值**由系统按难度公式发放（AI 只出题不定价，防止通胀）。
- **数据**存在浏览器 localStorage——换浏览器或清缓存会丢档，定期用底部「导出存档」备份。
- **界面**：学循同款结构——左侧导航（今日/商城/公告/数据/设置，今日带待办徽标），今日页含成长环（当日完成率）+ 宿主面板；设置里可切换「晨白（亮）/深空（暗）」主题。
- **属性对比**：每维以常人均值 100 为基准，进度条上灰线即基准线，旁边显示差值。
- **发布提醒（桌面版）**：后台线程每 60 秒读磁盘存档，按确定性算法判断发布时刻，到点弹 Windows toast——面板关着也能收到；面板已处理的槽位自动跳过。算法一致性由 `tests/plan_parity.py` 保证，改动 js/core.js 的 planDay 后务必重跑。
- **AI 周报**：数据页一键生成——AI 基于近 7 天完成数据（含每条任务的一句话完成记录）、系统公告，输出整体评价/亮点/问题/下周建议，结果存档并展示。
- **完成凭证**：点「完成」时可在任务卡内填一句话记录，写入存档与公告，并作为周报上下文。
- **任务池**：设置页可预设想反复做的任务——AI 出题优先采用；网关离线时降级池也先用它们。
- **难度自适应**：近 7 日完成率 ≥80% 时 AI 以挑战题为主，<40% 时以轻量题为主。
- **经济平衡**：`tests/economy_sim.py` 模拟 30 天三种场景，验证奖励公式与商城定价无恶性通胀/通缩（全勤上限约 2300 金币/月，低完成约 400）。
- **可靠性**：`settle()` 异常统一兜底（不再静默失败）；存档 `X-Save-Mtime` 乐观锁防双开互踩；AI 调用 20 秒硬超时，网关挂起时快速降级，界面不会卡在「系统推演中」。
- **自检**：底部「运行自检」按钮，或控制台 `GROWTH.selftest()`。
- **分段推进**：「先做 10 分钟」把 20 分钟以上的 ★★ 任务拆成两段——先领一半奖励（状态 `partial`），完成剩余补另一半，总额等于整奖。
- **补交拉力**：活跃窗口过半仍零完成时，系统追加一个轻量起步任务（难度 1 / ≤15 分钟，不走 AI），一天最多一次。
- **错过提醒的补救**：关机/睡眠/开会时提醒等于没发生——面板打开后，离线期到点的支线任务**按"看到的那一刻"重新计时**（不再从发布时刻算），超窗的突发任务**救回 1 次**（每日额度），离线期间到期、回来才发现的任务**给 2 小时补交窗口**；今日页顶部一条说明，任务卡带「重新计时 / 错过救回 / 补交窗口」徽标。宿主一直在却拖过 2 小时的突发任务仍按原规则收回，补救不发给拖延。
- **成就**：14 项（首胜 / 累计 / 连击 / 等级 / 属性 / 均衡 / 突发 / 全清 / 金币），解锁写公告并 toast，数据页可看进度。
- **商城攒钱进度**：每件奖励显示完成百分比与「还差 N 金币（约 M 个 ★★ 任务）」。
- **月度热力图**：最近 12 周按日着色，悬停看当天完成明细。
- **任务池批量**：设置页支持「标题|分类|难度|分钟」逐行导入，以及把近 7 天完成过的任务一键沉淀进池。
- **主题**：晨白 / 深空 / **跟随系统**（`prefers-color-scheme`，系统切换时实时跟随）。
- **网关超时保护**：AI 调用 20 秒硬超时，网关挂起时快速降级到内置池，界面不会卡在「系统推演中」。

## 系统周报

**数字由本地算，AI 只负责解读** —— 这是这个功能的核心设计。`weekMetrics()` 在 `core.js` 里算出结构化的统计，AI 收到的提示词里明确要求「不要编造数字，所有数量只能用给定的」，生成结果与指标分开存储（`S.lastReport = {text, metrics, source}`）。

指标卡显示：完成任务数、完成率（含与上周的 ▲▼ 对比）、有效行动天数、连续打卡、四维属性增量、投入最多维度、最需补强维度、统计区间与失效/收回明细。

**网关不可用时自动降级**：`callReport()` 捕获 AI 失败后改为 `localReport()`，用同一套本地指标拼出完整周报（整体评价/亮点/问题/建议），并在卡片上标注「离线生成 · 仅基于本地统计」。这个功能因此永远不会因为没网而空白。

**补救复盘**：周报指标卡多一行「补救复盘」——本周离开期间错过几次、按支线重计时/突发救回/补交窗口拆开、额度用光几天、最长一次离开多久，并与上周对比。结论由 `rescueInsight()` 给出三档（`ok` 时段匹配 / `note` 已被接住 / `warn` 作息错位）。反复错过**不是执行问题，而是发布时段与真实作息错位**，`warn` 时会直接建议调整活跃窗口。

**诊断直接接上修复**：`warn` 时结论内出现「把活跃窗口调到我实际的时段（18:30–22:00）」按钮，用 `suggestActiveWindow()` 从近 7 天真实**完成时刻**取 10%~90% 分位推算（两侧各留 30 分钟、窗口至少 3 小时、夹在 06:00–23:30），一键写入设置并同步设置页输入框。样本少于 3 次不建议（凭一两次数据改设置比不改更糟）；今日已发布的任务不受影响，次日生效。

**建议可落地**：周报底部有「把「体质」补强任务加入任务池」按钮，用 `suggestTasksFor()` 按最薄弱维度从候选池挑 3 条（优先低难度、短时长，排除已在池中的），一键写进任务池。这样「下周给体质排几个任务」不再是一句空话。

**任务池采用率**：数据页「任务池采用情况」卡回答「池子到底有没有用」——池内任务采用率、池内完成数、每条任务的发布/完成次数、从未被采用的条目。实现上，任务生成时用 `isFromPool()` 打 `task.fromPool` 来源标记（标题做归一化 + 包含匹配，容忍 AI 的轻微改写），老数据没有标记时按标题回推。

## 系统流机制

围绕「系统流小说」的核心套路实现，全部零依赖：

| 机制 | 说明 |
|---|---|
| **主线任务** | 把设置页的「成长目标」变成可追踪的长线：默认「三十天筑基」（30 个任务）。完成 1 个任务推进 1 格，达 1/3、2/3、100% 有里程碑播报，完成发额外奖励（EXP+200 ◈+300）。设置页可自定义名称与目标数（里程碑自动重算）。 |
| **连续签到阶梯** | 连击 3/7/14/30 天各发一次额外金币（30/80/200/500），每档只领一次，记录在 `S.streakClaimed`。 |
| **称号系统** | 14 个成就各自对应一个称号（「初醒者」「七日守约」「铁律之身」…）。设置页「佩戴称号」只列出已解锁的，佩戴后显示在宿主面板名字旁。 |
| **任务稀有度** | 普通 80%（×1）/ 稀有 17%（×1.3）/ **史诗 3%（×1.5）**。史诗有金色徽标、专属公告与卡片描边。稀有度按「日期+槽位」确定性掷骰，重开页面不会变。 |
| **每日赐福** | 每天确定性随机一个加成（体质/智力/精神/自律 ×1.5，或全能 ×1.2；30% 概率「平平无奇」）。今日页顶部显示，结算时按任务维度乘算，公告标注「赐福 ×1.5」。 |
| **任务连锁** | 完成智力/自律类任务有 25% 概率派生一个后续任务（带「连锁」徽标与 `chainedFrom` 来源），
限时 3 小时。派生时避开近 7 天（含当天）出现过的任务标题；近期都用过时退到最久没出现的那条，连「今天没用过」都满足不了才不发。 |
| **起步任务** | 活跃窗口过 60% 仍零完成时，追加一个 ★1、≤15 分钟的轻量任务（不走 AI，立刻可见）。取模板与连锁共用同一套近期避让规则，不会连续几天发同一个。 |
| **内置任务池** | `FALLBACK_POOL` 共 34 条（四个维度 × 难度 1/2/3，每格 2-4 条）。起步任务、连锁任务、AI 失败兜底都从这里取，所以每个维度/难度都必须有足够多条——早期自律★1 只有两条时，同一批标题会天天循环。 |
| **AI 任务查重** | 提示词里带上「今天已发布」与「近 7 天出现过」的标题；返回结果再过一遍 `dedupeTasks`：批内重名、与今天已有任务重名的一律丢弃，数量不足用近期没出现过的池模板补齐。提示词只是请求，模型不保证照做。 |
| **完成冷却** | 任务发布后 60 秒内「完成」按钮不可点（显示倒计时），防止卡片重排后误点——实测出现过「任务发布 3 秒就被点掉」，连锁因此套娃。常量 `COMPLETE_COOLDOWN_MS`。 |
| **完成可撤销** | 完成后 5 秒内弹「撤销」，回滚整份存档快照（奖励、主线进度、成就、连击、连锁一并退掉），比逐项手动回退可靠。常量 `UNDO_WINDOW_MS`。 |
| **已完成折叠** | 今日页把「已完成/已失效」折成一行开关，待办不会被一天的记录挤到屏幕外；收回的突发任务不折（那张卡本身就是在解释"为什么没了"）。 |
| **系统语气** | 冷酷 / 毒舌 / 温和 / 逗比，影响完成公告的措辞（`TONES`）。设置页可切换。 |
| **属性等级反馈** | 七个等级 F/E/D/C/B/A/S（含中文名：未觉醒/初显/入门/熟练/精通/卓越/超凡）。属性条下方常驻「距 D 还差 36」，跨级时**系统公告 + 金色 toast + 呼吸高亮**，并在数据页「属性突破」卡留痕（维度/等级/数值/时间）。阈值集中在 `RANK_LADDER`，`attrRank` 与跨级播报共用一套数字。 |

结算奖励链路：**基础公式 → 稀有度乘数 → 当日赐福倍率**。分段推进领半奖时不吃稀有度与赐福加成（避免刷半奖套利）。

## 可靠性设计

- **结算异常不再静默**：`settle()` 的调用统一走 `runSettle()` 兜底 catch，出错会 toast + 控制台打印（此前 async 被 `.then` 吞掉，出 bug 时界面只是"一片安静"）。
- **存档冲突检测**：`/api/save` 用 `X-Save-Mtime` 做乐观锁，磁盘被另一处（桌面版 / 浏览器版双开）改写时返回 409，前端不覆盖而是按 `updatedAt` 采用较新的一份并提示，避免互踩丢档。
- **补交宽限**：支线截止 = min(当日末, 发布 + 6 小时)；起步任务截止 = min(当日末, 此刻 + 2 小时)；往日超时任务保留 2 小时宽限期，仍在今日页以「逾期待补交」显示。
- **错过提醒的补救**（`rescueDecision`，core.js 纯函数）：
  - **判定**：面板每轮结算写一次心跳（独立 localStorage 键 `growth_system_lastseen`，**不进存档**——否则心跳会把 `updatedAt` 一直顶新，双开时的 409 冲突判定跟着失真；且只在标签页可见时写，后台标签/最小化窗口都算离开）。两次心跳间隔 ≥30 分钟 → 这段时间提醒没人接收，期间的到点槽位按「错过」处理；发布时刻过去 10 分钟以内不算错过。
  - **支线**：截止从"此刻"重算（6 小时，不越过当日末），而不是从发布时刻算——10:00 的题 15:00 才看到，原来只剩 1 小时。
  - **突发**：未超 2 小时的给足 2 小时；已超窗的救回 1 次/天（`RESCUE_PER_DAY`），额度用尽后照旧收回并在卡片上写明原因。
  - **已到期**：今日任务若在离线期间到期（离开时还活着、回来已经死了），不注销，改为 2 小时补交窗口（`rescued:'grace'`）；离开前就已经超时的照旧失效。
  - **边界**：宿主一直在线却拖过 2 小时的突发任务仍收回——补救是给"没收到提醒"的人，不是给拖延的人。
  - **不跨天**：突发任务的 2 小时倒计时一律夹到当日 23:59。否则 23:00 触发的任务截止会落到次日 01:00，变成一个挂在昨天记录里、次日还能完成的幽灵任务（会连带污染次日连击与统计）。
  - **可观测**：当天记录 `S.days[today].rescue`（错过数/离开时长/支线与突发各几个），今日页顶部渲染说明条，任务卡带徽标，公告留痕。
  - **额度透明**：救回额度（`RESCUE_PER_DAY`）不再是隐形的——今日页在「当天有突发任务或额度已被用」时显示常驻状态条：`今日突发救回额度 1/1` + 圆点可视化；用光后转为红色虚线并提示「已用完 · 今天再错过突发任务将直接收回」。原本只有「错过且额度耗尽」时才被告知，那时已没有余地。
- **提醒不连弹**：`notifier.py` 一轮里多个槽位同时到点（睡眠唤醒/关机一天后回来）合并成一条 toast，并说明面板打开后会重新计时。
- **突发收回有提示**：超窗 2 小时被收回的突发任务会写公告 + toast，不再无声消失。
- **幂等结算**：完成/放弃走统一守卫并记录 `settledAt`，重复触发不会双发奖励。
- **时区变更自愈**：按日记录 `tzOffset`，检测到变化时保留已完成槽位、重排未发布槽位。
